# JSONL worker (experimental)

`opencrowd worker --protocol jsonl --agent-home /path/to/home --demo` runs the existing agent loop with a scripted model and real local file tools. It has no paid execution or local wallet fallback. Ordinary CLI commands keep their existing configuration and provider behavior.

stdin accepts protocol-v1 commands from `@opencrowd/protocol`; stdout emits only validated protocol events. Diagnostics go to stderr. Keep stdin open to submit cancellation while a run is active. Closing stdin drains the active run and exits.

The caller owns command IDs, run IDs, and preferably session IDs. Re-deliver the exact command envelope after a process interruption. Reusing an ID with different contents is rejected. Completed commands are acknowledged without another model/tool execution. Waiting runs resume only when the cause, session, and pending operation match.

`metadata/worker.json` contains the authoritative checkpoint and command acknowledgements. Non-secret configuration and session files live beneath the explicit home. Session paths are recalculated when restoring to another location. Checkpoints are atomically replaced and synced before terminal outcomes. Model requests receive a stable operation ID; a remote payment adapter must use that ID for reconciliation and must never create another authorization for an ambiguous payment.

An interrupted shell action with no recorded result fails for manual reconciliation instead of automatically replaying its side effects. Local file writes are repeatable, and recorded tool results are reused. The supervisor must copy artifacts and the quiescent home before acknowledging the terminal event; it must recover a missed artifact event by listing the checkpointed session files.

For a supervised hosted model, replace `--demo` with `--bridge-socket /absolute/path/to/model.sock`. Exactly one mode is required. The Unix socket accepts a bounded `POST /model` request containing the run, session, stable model-operation ID, messages, and built-in tool definitions. A response is either `{status:"complete",response:{content,toolCalls,finishReason?}}` or `{status:"paused",outcome,operationId,message}`. The supervisor authenticates remote requests and must constrain them to the current run; the worker receives no signing credentials. Interrupted requests pause for payment reconciliation without a provider fallback.

Before each `POST /model` the worker trims the replayed history to 48 KB (`trimHostedMessages`, measured as the JSON byte length of the messages array) so long-running follow-ups do not outgrow the bridge's 64 KB request limit. Every `system` message, the first `user` message, and the last four messages are always sent untouched. Older tool outputs longer than 300 characters are replaced first with `{"truncated":true,"note":...}`; if that is not enough, whole older turns are dropped oldest-first, with an assistant message and its tool results removed together so the model never sees an orphan result; as a last resort the largest remaining non-system message (other than the latest user message) is cut to its last 6000 characters with a `[…trimmed…]` prefix. Trimming is pure and deterministic and does not alter the checkpoint, which keeps the full conversation.

A non-200 bridge response is classified by its JSON body `{error, message?, status?, paid?}`. Only an explicit `paid: false` proves that nothing was charged: the run then finishes with outcome `failed` and `message` (or `The model request was rejected (<error>)`) as the summary, which the host should show to the user. Any other failure — a body without `paid`, `paid: true`, a non-JSON body, a transport error, or the 90-second socket timeout — still pauses the run with `payment_unknown` for reconciliation, exactly as before.

The same socket accepts a bounded `POST /tool` request for supervisor-executed tools (`HOSTED_ONLY_TOOL_NAMES`: `deploy_service`, `request_secret`, `vault_request` and `automations`). The body carries the run, session, tool name, and arguments; for `deploy_service` the worker inlines the entry artifact's source, while `request_secret` and `vault_request` forward their arguments untouched. The response is a plain `{ok, data}` or `{ok:false, error}` tool result. Hosted-only tools are advertised only to hosted models, are refused by the local executor, and are memoized per checkpoint turn like every other tool. A lost tool response is reported to the model as an error rather than treated as a payment, because deployments are idempotent per slug and secret requests are idempotent per name.

With `--bridge-socket` the worker also builds a hosted economy gateway (`createHostedEconomy`), so the model gets the same paid-capability tools as the local CLI: `find_paid_service`, `inspect_paid_service`, `call_paid_service`, and `review_paid_service` (plus `get_wallet_status` and `bridge_usdc`, which moves the agent's own USDC between Base, Solana and Tempo through the supervisor's `economy.transfer` tool). Their definitions are sent to the bridge in `POST /model` `tools` alongside the built-in ones. Discovery reads CrowdCode's public `GET /api/services` (cached for 60 seconds) and ranks rows by token overlap against the name, endpoint and slug; only `payment_provider: x402` rows are `payable`. Inspection probes the endpoint unauthenticated (no payment) and classifies every offer, x402 `payment-required` entries and MPP `WWW-Authenticate: Payment` challenges alike: Base USDC → `x402-base`, Solana USDC (`exact`) → `x402-solana`, Tempo USDC.e `charge` → `mppx`, Monad and anything else `unsupported` for hosted agents. The result lists each offered network with its price; the quoted ceiling is the dearest payable offer because the hosted gateway picks the network at payment time from the agent's per-network balances. The input/output schema comes from the discovery extension; reputation comes from `GET /api/services/:id`, and an unlisted endpoint is treated as unproven rather than blocked. A paid call waits `SERVICE_GATEWAY_TIMEOUT_MS` plus 30 seconds on the socket, longer than the supervisor and gateway behind it. If the socket is still lost, the same `economy.pay` request (same `purchase_request_id`) is posted once more after a short pause: the gateway replays a finished purchase instead of paying twice, an in-flight one answers `payment_unknown`, and the purchase is then recorded as `unknown` with reason `timeout` or `transport`. A request the socket refused outright is not re-posted.

Every credentialed step crosses the same socket as a `POST /tool` with `name` `economy.pay`, `economy.review` or `economy.balance` (see `design-docs/HOSTED_PAID_SERVICES.md` in the parent repository for the contract). `economy.pay` carries a fresh `purchase_request_id` per attempt, the CrowdCode `service_id`, the url, method, body and `max_cost_cents`; a `paid_success`/`paid_failure` reply becomes a paid receipt (tx hash, payee, USDC amount) stored for the required review, `expected_payment_required` makes the worker fetch the free endpoint itself, `payment_unknown` or a lost reply is recorded as an ambiguous purchase that is never retried, and any other code is surfaced to the model with that code. Rails the hosted gateway cannot pay (Monad, other chains or tokens) are refused before the bridge is called, with a message listing what hosted agents can pay; the paid receipt's rail follows the network the gateway reports. When `economy.balance` reports `networks`, the financial snapshot carries per-network balances. The loop refuses to complete while a paid purchase still needs its `review_paid_service` call. Economy tool calls are memoized per checkpoint turn like built-in tools and appear in `tool.started`/`tool.finished` events; a `call_paid_service` whose result was lost mid-payment fails the run for manual reconciliation, like `run_shell`. If the bundled knowledge tree cannot be loaded the run falls back to the static capability index instead of failing.

`request_secret` takes `name` (`^[A-Z][A-Z0-9_]{1,63}$`), `allowed_hosts` (hostnames the secret may be sent to), and `reason` (one sentence for the user). The supervisor asks the user to add the value to the agent's encrypted vault through the host UI and returns `{status: "requested" | "active", placeholder?}`; the worker and the model never see the value. The hosted system prompt tells the model to request secrets by name this way, never to ask the user to paste a secret into the chat, and to consume them through `deploy_service` `secrets` as `env.NAME`.

`vault_request` takes `url` (https only), optional `method`, `headers`, string `body`, and `reason`. The model writes `{{SECRET_NAME}}` wherever a vault value belongs; the host substitutes the real value at its network boundary only for hosts the owner approved for that secret, refreshes managed OAuth 2.0 tokens itself, and returns `{status, content_type, body, truncated}` with the value never present. A host answering `host_approval_required` means the owner must allow the domain in their UI; the prompt tells the model to stop and say so rather than shop for a paid substitute. A workspace file (up to 25 MB) can be the body via `body_artifact`; the supervisor uploads it through the normal artifact path first and the host reads it back by artifact id, raw or as a multipart part named `body_field` with `form_fields`. `run_shell` allows up to 300 s per command so renders and downloads fit.

`tool.started` events carry a redacted `input` summary produced by `summarizeToolInput` so hosts can show progress without leaking data: `run_shell` → the first 200 characters of the command, `save_file`/`read_file`/`list_files` → the path, `deploy_service` → slug, name and price, `request_secret` → name and allowed hosts, `vault_request` → method, url and reason (never headers or body), `complete_session` → the first 200 characters of the final message, `find_paid_service` → query or origin, `inspect_paid_service` → url and method, `call_paid_service` → url, method and `max_cost_cents`, `review_paid_service` → purchase id and rating. File contents and secret values are never included; other tools carry no summary.

Tests include a real `SIGKILL` between a completed file tool and the next model response, followed by process restart: the artifact and single user prompt survive, the completed tool is not repeated, and the next model operation keeps its original ID. Hosted subagent checkpointing and production image rollouts remain separate integration gates.

### Moving funds between networks (`bridge_usdc`)

Hosted agents hold USDC on several networks, and a payment can only spend the
balance of the network it pays on. `bridge_usdc` moves the agent's own USDC
between Base, Solana and Tempo. The worker never chooses a destination:
control always sends to the agent's own address on the target network.

- `quote_only: true` posts `economy.transfer {action: "quote"}` and returns the
  fee, the expected and minimum received amounts, and whether the owner's
  policy would require approval. Nothing moves.
- Otherwise the worker posts `{action: "execute", operation_id}`. The operation
  id is derived from the run and the tool call, so a replayed or re-posted call
  returns the same transfer instead of moving twice. Control applies the
  owner's spending policy to the fee, as for a paid call: ask mode, the
  per-call limit or the query budget create an approval and the supervisor
  answers `approval_required`. The worker then pauses the run with
  `waiting_for_approval` and that operation id, and the approved resume repeats
  the same call.
- An executed move is followed with `{action: "status"}` every few seconds for
  up to 150 seconds and returns both transactions and the received amount. A
  move still pending after that is returned with its `transfer_id`, which the
  model can pass later to check it.

When a paid call fails with `funding_required`, the hosted adapter appends the
agent's available balance per network and, when another network holds enough,
the `bridge_usdc` call that would make the purchase payable. The hosted system
prompt tells the model to move funds and retry the same call in that case.
